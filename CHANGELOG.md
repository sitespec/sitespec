# SiteSpec changelog

SiteSpec uses a synchronized release train for all public npm packages.
Package-specific changelogs are generated by Changesets during version PRs; this repository changelog summarizes every SiteSpec release.

## Unreleased

- Added `sitespec migrate audit <url>` for evidence-first migration of existing production sites. Audits capture fixed desktop/tablet/mobile screenshots, DOM and layout evidence, computed design inventory, media inventory, section candidates, direct leaf-UI observations, and machine-readable metadata without generating SiteSpec source.
- Added `sitespec migrate segment <audit>` as a live Chrome/Chromium DOM picker. Reviewers can inspect exact roots, move through parent/child/sibling candidates, switch between Inspect and Interact modes, name logical blocks, group multiple roots, batch Merge/Ungroup/Delete existing blocks, update Header/Footer roots in place, reload with state restoration, and persist reviewer-owned `segments.json` evidence.
- Added `sitespec migrate design <audit...>` for deterministic multi-page Design System analysis. It preserves exact foundations while generating normalized token candidates, section rhythm, a rationalized foundation proposal, reusable section/component families, direct leaf-UI families, shell candidates, media roles, provenance, and confidence.
- Added responsive manual-root remeasurement across audit refreshes. Exact selectors are tried first with guarded DOM-fingerprint fallback, and grouped roots resolve enclosing boundary containers so section-rhythm analysis can use real outer section padding rather than inner content geometry.
- Added explicit foundation review/materialization. Accepted, rejected, pending, and provisional decisions are SHA-bound to the proposal; materialization can carry compatible target semantic API tokens provisionally and only mutates canonical `design/tokens.json` through explicit `--apply --replace`.
- Added component and leaf-UI review/contract stages. Accepted reusable section families generate `component.yaml` previews; accepted UI families generate `ui.yaml` previews with a required canonical `default` variant. Heuristic Card/Badge boundaries and unresolved form-control roles remain review-required instead of becoming automatic primitives.
- Added reviewed shell contracts and migration-owned Design System staging. Contract-only staging excludes pending/rejected families and reports missing Astro implementations/fonts as blockers rather than fabricating placeholders.
- Added `sitespec migrate implementations infer <analysis>` to generate migration-owned Astro implementation previews and additive semantic token aliases from accepted contracts plus saved DOM/computed-style evidence. Production HTML and unobserved interactive/runtime behavior are not copied or invented.
- Extended `migrate design-system materialize` to consume current implementation inference, copy only expected accepted implementations, run Design System lint, and report executable `implementation-staging` while keeping local font binaries and uncaptured interaction states as explicit fidelity follow-up.
- Added Chrome/Chromium auto-detection with `--browser-path` / `SITESPEC_CHROME_PATH`, ownership-safe cleanup for generated migration directories, and `.sitespec/audit/` + `.sitespec/migration/` to the default Git ignore rules.
- Advanced the agent protocol to version 7 with discovery for audit, segmentation, design analysis, foundation/UI/component/shell review, implementation inference, contract staging, and implementation staging.
- Fixed Design System inference/validation interoperability for transparent backgrounds: color-only inference emits `background-color`, transparent/CSS-wide background keywords are not rejected as raw colors, and staging lint blockers include the failing path/declaration.

## 0.5.0 — Media & SEO

- Added a build-time image pipeline with responsive widths, `srcset`/`sizes`, AVIF/WebP derivatives, intrinsic dimensions, validation, crop/aspect ratio, and focal-point cropping.
- Added the generated `SiteImage.astro` renderer primitive and moved the starter hero onto the media contract.
- Added site/page SEO controls for canonical URLs, hreflang, richer Open Graph/Twitter metadata, and Schema.org JSON-LD graphs.
- Added deterministic generated social images with per-page overrides/fallbacks.
- Expanded static metadata generation to sitemap hreflang alternates, configurable `robots.txt`, `llms.txt`, and RSS.
- Served sitemap, `robots.txt`, `llms.txt`, and RSS from the development server as well as production builds, using the same metadata generator.
- Expanded `examples/marketing` into an end-to-end v0.5 showcase for media, generated/explicit social images, JSON-LD, reciprocal hreflang, noindex, sitemap, robots, `llms.txt`, and RSS.
- Added post-build HTML guarantees for canonical/description/social metadata, JSON-LD, image alt text, and v0.5 image dimensions.
- Fixed v0.5 starter/media contract integration so the default project validates cleanly, image accessibility errors are reported by the media validator, and root hreflang URLs normalize to the root canonical.
- Upgraded the default starter and marketing example to `specVersion: "0.5"`.

## 0.4.0 — Design Systems

- Made `design-system.yaml` a first-class, schema-validated Design System contract with stable identity and semantic version metadata.
- Added explicit exported UI primitive, section component, and section preset libraries.
- Formalized the outer-gutter/inner-container layout convention through semantic layout-token references.
- Added Design System themes as semantic-token override sets and site-level theme selection.
- Added named shell packs and site-level shell selection; renderers no longer have to assume only `shell/default.astro`.
- Added controlled `design/extensions.json` token extension rules: each primitive/semantic layer can be `locked` or `additive`, and additive extensions cannot override pack-owned token paths.
- Added `site spec design-system --json` inspection plus the dedicated `design-system --json` pack inspection surface.
- Added source-copy Design System packaging and installation with `design-system pack` and `design-system install`, preserving site-owned token extensions and avoiding runtime package dependencies.
- Updated the default starter and marketing example to `specVersion: "0.4"`, including a default/dark theme pair and a formal Design System contract.
- Advanced the stable agent protocol to version 4 and exposed Design System capabilities/workflows to agents.

## 0.3.0 — Content

- Added typed content collections with JSON Schema-backed entries in Markdown, YAML, and JSON.
- Added generic collection relations and canonical relation links.
- Added content-driven routes and `entry:` references for resolved entry data.
- Added declarative content queries with filtering, deterministic sorting, draft handling, and pagination.
- Added `query:` references and content inspection for collections and entries.
- Added base-path rebasing for links produced from rendered Markdown/content data.
- Upgraded the starter to demonstrate a small posts collection, content-driven detail pages, and query-generated pagination; moved the broader relation/taxonomy showcase to `examples/marketing`.

## 0.2.2 — Starter fixes

- Switched the default starter typography to bundled, self-hosted Inter.
- Changed the pagination showcase to real static routes so page state changes without client JavaScript.
- Kept the synchronized release packages aligned with the starter/renderer fixes.

## 0.2.1 — Executable composition showcase

- Expanded the v0.2 starter into an executable composition reference with dynamic feature routes and `param:` references.
- Reused section presets across pages and demonstrated named navigation references.
- Added a pagination component backed by the core pagination type.
- Added bundled local WOFF2 font declarations and complete semantic site assets.
- Added richer project inspection/bootstrap documentation for agents.
- Fixed renderer rebasing of pagination `previousHref`/`nextHref` values under deployment base paths such as GitHub Pages.

## 0.2.0 — Composition

- Added formal UI primitives as an internal composition layer below page sections.
- Added reusable section presets referenced with `section:<id>`.
- Added deterministic dynamic route expansion with explicit `page.paths` and route-parameter references.
- Added the pagination core prop type.
- Expanded agent-readable inspection for composition capabilities.
- Updated the default starter to dogfood the v0.2 composition model.

## 0.1.0 — Initial contract

- Introduced the Git-native SiteSpec project contract for static websites.
- Added site/page/component schemas, deterministic source validation, registered section components, routes, SEO, navigation/assets, and static Astro rendering.
- Established the repository as the source of truth and generated `.site/`/`dist/` as disposable output.
- Added project-local CLI workflows for inspection, validation, build, preview, and controlled component creation.
