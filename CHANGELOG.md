# SiteSpec changelog

SiteSpec uses a synchronized release train for all public npm packages.
Package-specific changelogs are generated by Changesets during version PRs; this repository changelog summarizes every SiteSpec release.

## 0.4.0 — Design Systems

- Made `design-system.yaml` a first-class, schema-validated Design System contract with stable identity and semantic version metadata.
- Added explicit exported UI primitive, section component, and section preset libraries.
- Formalized the outer-gutter/inner-container layout convention through semantic layout-token references.
- Added Design System themes as semantic-token override sets and site-level theme selection.
- Added named shell packs and site-level shell selection; renderers no longer have to assume only `shell/default.astro`.
- Added controlled `design/extensions.json` token extension rules: each primitive/semantic layer can be `locked` or `additive`, and additive extensions cannot override pack-owned token paths.
- Added `site spec design-system --json` inspection plus the dedicated `design-system --json` pack inspection surface.
- Added source-copy Design System packaging and installation with `design-system pack` and `design-system install`, preserving site-owned token extensions and avoiding runtime package dependencies.
- Updated the default starter and marketing example to `specVersion: "0.4"`, including a default/dark theme pair and a formal Design System contract.
- Advanced the stable agent protocol to version 4 and exposed Design System capabilities/workflows to agents.

## 0.3.0 — Content

- Added typed content collections with JSON Schema-backed entries in Markdown, YAML, and JSON.
- Added generic collection relations and canonical relation links.
- Added content-driven routes and `entry:` references for resolved entry data.
- Added declarative content queries with filtering, deterministic sorting, draft handling, and pagination.
- Added `query:` references and content inspection for collections and entries.
- Added base-path rebasing for links produced from rendered Markdown/content data.
- Upgraded the starter to demonstrate a small posts collection, content-driven detail pages, and query-generated pagination; moved the broader relation/taxonomy showcase to `examples/marketing`.

## 0.2.2 — Starter fixes

- Switched the default starter typography to bundled, self-hosted Inter.
- Changed the pagination showcase to real static routes so page state changes without client JavaScript.
- Kept the synchronized release packages aligned with the starter/renderer fixes.

## 0.2.1 — Executable composition showcase

- Expanded the v0.2 starter into an executable composition reference with dynamic feature routes and `param:` references.
- Reused section presets across pages and demonstrated named navigation references.
- Added a pagination component backed by the core pagination type.
- Added bundled local WOFF2 font declarations and complete semantic site assets.
- Added richer project inspection/bootstrap documentation for agents.
- Fixed renderer rebasing of pagination `previousHref`/`nextHref` values under deployment base paths such as GitHub Pages.

## 0.2.0 — Composition

- Added formal UI primitives as an internal composition layer below page sections.
- Added reusable section presets referenced with `section:<id>`.
- Added deterministic dynamic route expansion with explicit `page.paths` and route-parameter references.
- Added the pagination core prop type.
- Expanded agent-readable inspection for composition capabilities.
- Updated the default starter to dogfood the v0.2 composition model.

## 0.1.0 — Initial contract

- Introduced the Git-native SiteSpec project contract for static websites.
- Added site/page/component schemas, deterministic source validation, registered section components, routes, SEO, navigation/assets, and static Astro rendering.
- Established the repository as the source of truth and generated `.site/`/`dist/` as disposable output.
- Added project-local CLI workflows for inspection, validation, build, preview, and controlled component creation.
